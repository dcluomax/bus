# ST Tracker (bus) — Architecture & Feature Overview

A small Express + static-web transit arrival tracker for Sound Transit Link light rail, packaged for Android and iOS with Capacitor.

## 1. What this project is

`bus` is a real-time arrival tracker for Sound Transit's Link light rail in the Puget Sound region. Despite the repository name, it is not a message bus and not a service-definition repo: it is a single-purpose web application with a Node.js/Express backend that proxies transit data, a plain-JavaScript front end, and two native mobile shells (Android and iOS) generated by Capacitor.

The backend is one file, `src/server.js` (679 lines), which serves the static front end from `public/` and exposes a five-route JSON API. It reads live vehicle positions and trip updates from Sound Transit's public GTFS-RT protobuf feeds on Amazon S3, with a fallback to the Puget Sound OneBusAway (OBA) REST API when the protobuf feed yields nothing for the requested stop. Station metadata for the 1 Line and 2 Line is hard-coded in the server rather than derived from a GTFS schedule file.

The front end is `public/app.js` (1099 lines of un-bundled ES5-style JavaScript) plus `public/index.html`, `public/style.css` and `public/manifest.json`. It reimplements the station table client-side, tracks the device's GPS position to auto-select the nearest station, shows walking-time estimates, and lets the user set a per-train reminder notification.

The mobile shells are the standard Capacitor scaffolding: `android/` (Gradle project, one custom `MainActivity.java` that adds NFC foreground dispatch) and `ios/` (Xcode project with the default `AppDelegate.swift`). The web assets are copied into a generated `www/` directory at build time by `npm run build:web` (`package.json:10`).

The repository tracks 92 files. Roughly 8 of them are hand-written code (`src/server.js`, `public/app.js`, `public/capacitor-bridge.js`, `public/sw.js`, `public/index.html`, `public/style.css`, the Android `MainActivity.java`, and the iOS `AppDelegate.swift`); the remainder are native project scaffolding, image assets, and lockfiles.

## 3. Architecture

```
                 ┌───────────────────────────────────────────────┐
                 │  Sound Transit GTFS-RT (public S3 protobuf)   │
                 │  tripupdates.pb / vehiclepositions.pb /       │
                 │  alerts.pb                                    │
                 └───────────────┬───────────────────────────────┘
                                 │ HTTPS (Accept: application/x-protobuf)
                                 ▼
  ┌──────────────────────────────────────────────────────────────────┐
  │  Node 20 process — src/server.js (Express)                        │
  │                                                                  │
  │   express.static(public/) ──► /            app.js, style.css     │
  │   GET /api/lines                                                 │
  │   GET /api/stations                                              │
  │   GET /api/arrivals/:stationId  ──► in-process Map cache (3 min) │
  │   GET /api/alerts                                                │
  │   GET /api/docs                                                  │
  │   GET /health                                                    │
  │                                                                  │
  │   fallback: OneBusAway REST (api.pugetsound.onebusaway.org)      │
  └───────────────────────┬──────────────────────────────────────────┘
                          │  HTTP JSON
                          ▼
  ┌──────────────────────────────────────────────────────────────────┐
  │  Browser / Capacitor WebView — public/                           │
  │    app.js:  state (line, station, direction, GPS, onboard flag)  │
  │    index.html + style.css: line buttons, station <select>,       │
  │                         arrival cards, alert cards, NFC modal     │
  │    sw.js:   service worker, network-first cache for static assets│
  │    capacitor-bridge.js: native shims (present, but unlinked)     │
  └───────────────────────┬──────────────────────────────────────────┘
                          │  Capacitor plugin bridge / Android Intent
                          ▼
  ┌──────────────────────────────────────────────────────────────────┐
  │  Native shells                                                    │
  │    android/  MainActivity extends BridgeActivity; NFC foreground   │
  │              dispatch, tag → evaluateJavascript into the WebView  │
  │    ios/      AppDelegate.swift (Capacitor default)                │
  │    native geolocation, haptics, push notifications, splash screen │
  └──────────────────────────────────────────────────────────────────┘
```

The project is a two-tier web application. The Express server owns all knowledge of transit data and holds the only outbound network credentials; the browser never talks to Sound Transit or OneBusAway directly, it only calls the same-origin `/api/*` routes. The static bundle and the JSON API are served by the same Express process on the same port, so the front end's `fetch('/api/arrivals/...')` calls (`public/app.js:570`) are same-origin.

Trust and process boundaries are limited. The browser→server hop is unauthenticated and unencrypted in the default Compose configuration (the container publishes port 30089 over plain HTTP; `capacitor.config.ts:9` sets `cleartext: true` and the commented-out `server.url` points at `http://<your-server>:30089`). The server→Sound Transit hop is HTTPS to a public S3 endpoint. The OneBusAway fallback sends an API key as a `key=` query parameter (`src/server.js:386`); the default value is the literal string `TEST` (`src/server.js:14`), which is a well-known OneBusAway test key rather than a secret.

The mobile shell adds a third boundary: native code reaches the WebView through a string of JavaScript built by concatenating the tag serial number into source text (`android/app/src/main/java/com/maxluo/sttracker/MainActivity.java:103`). The serial is hex-encoded, so it is not injectable in practice, but the pattern is string interpolation rather than a structured bridge call.

There is no database. All state lives in process memory (the server's response cache), in browser cookies, in `localStorage`, and in the service worker cache. The repo contains no migration files and no schema definitions.

## 5. Data flow

### 5.1 Primary: arrival lookup

1. The page loads `public/app.js` (`public/index.html:80`), and `init()` runs (`public/app.js:726`): it clears legacy cookies, restores `bus_line` / `bus_direction` / `bus_station`, populates the station dropdown, then calls `fetchArrivals()` and `fetchAlerts()` (`public/app.js:739`).
2. `fetchArrivals()` issues `GET /api/arrivals/<stationId>?direction=<dir>&line=<line>` (`public/app.js:570`).
3. Express matches the route at `src/server.js:488`, validates `line` and `direction` via `validateLineAndDirection` (`src/server.js:444`), and resolves the station either from the named line or by scanning every line (`src/server.js:497`).
4. The route computes a cache key `arrivals:<lineId>:<stationId>:<direction>` and returns the cached payload immediately if present (`src/server.js:515`).
5. On a miss it selects the target stop IDs — the single directional stop, or all of `station.stopIds` when no direction was given (`src/server.js:522`).
6. `fetchGtfsRt()` downloads `tripupdates.pb` with `Accept: application/x-protobuf` and decodes it into a `FeedMessage` (`src/server.js:357`, `src/server.js:366`).
7. `parseTripUpdates()` walks `entity[].tripUpdate.stopTimeUpdate[]`, keeps entries whose `stopId` matches, and emits `{tripId, routeId, directionId, stopId, arrivalTime, arrivalDelay, departureTime, departureDelay, scheduleRelationship}` (`src/server.js:414`, `src/server.js:421`).
8. If nothing matched, the OBA fallback runs per stop ID and its `arrivalsAndDepartures` entries are pushed into the same array (`src/server.js:535`, `src/server.js:540`).
9. The server deduplicates by `tripId` preferring the entry with `predicted` set, filters out arrivals in the past, sorts by `arrivalTime` and truncates to 10 (`src/server.js:563`, `src/server.js:578`).
10. The response `{station, direction, timestamp, arrivals}` is cached and returned as JSON (`src/server.js:583`, `src/server.js:591`).
11. The client renders one card per arrival and schedules the next poll at the first future arrival time plus 5 seconds (`public/app.js:487`, `public/app.js:470`).

### 5.2 Geolocation → station auto-selection

1. `startLocationWatch()` checks that the page is on HTTPS or localhost before touching the geolocation API (`public/app.js:371`).
2. `getCurrentPosition` resolves the first fix, then `watchPosition` is registered with `{enableHighAccuracy:true, timeout:10000, maximumAge:30000}` (`public/app.js:386`, `public/app.js:392`).
3. `onPositionUpdate()` stores the fix, finds the nearest station with the Haversine formula in `getDistance()` (`public/app.js:174`, `public/app.js:320`).
4. Within 50 m the user is flagged `isOnboard` and the current station tracks the movement; beyond 500 m the flag clears (`public/app.js:330`, `public/app.js:343`).
5. Unless the user has manually picked a station, a nearest station under 5 km is auto-selected (`public/app.js:349`).
6. `updateWalkTimeDisplay()` renders either the distance/walk estimate or the onboard "next station ETA" computed from a nominal 40 km/h train speed (`public/app.js:276`, `public/app.js:303`).

### 5.3 ORCA card scan (Android native path)

1. `MainActivity.onCreate()` obtains the `NfcAdapter` and builds a `PendingIntent` for foreground dispatch with NDEF, tech and tag intent filters (`android/app/src/main/java/com/maxluo/sttracker/MainActivity.java:32`, `android/app/src/main/java/com/maxluo/sttracker/MainActivity.java:43`).
2. `onResume()` enables foreground dispatch and `onPause()` disables it (`android/app/src/main/java/com/maxluo/sttracker/MainActivity.java:70`, `android/app/src/main/java/com/maxluo/sttracker/MainActivity.java:81`).
3. `onNewIntent()` matches the three NFC actions, extracts `EXTRA_TAG` and hex-encodes the tag id (`android/app/src/main/java/com/maxluo/sttracker/MainActivity.java:92`, `android/app/src/main/java/com/maxluo/sttracker/MainActivity.java:99`).
4. A JavaScript snippet is built by string concatenation and evaluated in the Capacitor WebView (`android/app/src/main/java/com/maxluo/sttracker/MainActivity.java:103`, `android/app/src/main/java/com/maxluo/sttracker/MainActivity.java:116`).
5. The snippet calls `window.STNative.playNfcSound()` and `window.STNative.showNfcPopup(serial)` when the native shim is present, otherwise falls back to directly manipulating the `nfc-modal` element and playing `sounds/orca-scan.mp3` (`android/app/src/main/java/com/maxluo/sttracker/MainActivity.java:106`).

The web-only variant of this flow lives in `public/app.js:940` (`startNFCScan`), using the `NDEFReader` Web API and the `reading` event.

## 6. Data model & storage

### 6.1 Station records (server, `src/server.js:25`)

The 1 Line table uses the shape:

```js
'westlake': {
  name: 'Westlake',
  southbound: '40_1108',     // OBA stop id, southbound platform
  northbound: '40_1121',     // OBA stop id, northbound platform
  lat: 47.611572,
  lon: -122.33672
}
```

The 2 Line table additionally carries a `stopIds` array listing both platforms (`src/server.js:215`):

```js
'wilburton': {
  name: 'Wilburton',
  stopIds: ['40_E19-T1', '40_E19-T2'],
  southbound: '40_E19-T1',
  northbound: '40_E19-T2',
  lat: 47.617909,
  lon: -122.183806
}
```

Stop-ID suffixes encode platform: `-T1` is southbound and `-T2` northbound (`src/server.js:211`); a handful of older 1 Line stations use bare numeric ids such as `40_1108` instead.

### 6.2 Line records (`src/server.js:302`)

```js
'2_line': {
  name: '2 Line',
  color: '#E31837',
  stations: LINK_2_LINE_STATIONS,
  directions: {
    southbound: 'Southbound (to Bellevue)',
    northbound: 'Northbound (to Redmond)'
  }
}
```

The 1 Line colour is `#0072CE` (`src/server.js:305`).

### 6.3 Client-side station mirror (`public/app.js:19`)

The browser keeps its own table with `name`, `lat` and `lon` per station, plus a `stationOrder` array that the server does not have. The station order is the basis of the onboard "next station" calculation. The two tables are duplicated by hand and can drift; the client copy contains no stop IDs.

### 6.4 API response shapes

`GET /api/arrivals/:stationId` (`src/server.js:583`):

```json
{
  "station": "Wilburton",
  "direction": "southbound",
  "timestamp": 1750000000000,
  "arrivals": [
    {
      "tripId": "…",
      "routeId": "40_2LINE",
      "directionId": 0,
      "stopId": "40_E19-T1",
      "arrivalTime": 1750000600000,
      "arrivalDelay": 0,
      "departureTime": 1750000600000,
      "departureDelay": 0,
      "scheduleRelationship": 0
    }
  ]
}
```

When the OBA fallback supplies the data, the entries instead carry `routeShortName`, `tripHeadsign`, `scheduledArrivalTime`, `predictedArrivalTime`, `predicted`, `vehicleId` and `distanceFromStop` (`src/server.js:540`). `arrivalTime` is epoch milliseconds — GTFS-RT times are epoch seconds and are multiplied by 1000 (`src/server.js:426`).

`GET /api/alerts` (`src/server.js:618`):

```json
{
  "alerts": [
    {
      "id": "…",
      "headerText": "…",
      "descriptionText": "…",
      "cause": 2,
      "effect": 4,
      "activePeriod": [{ "start": 1750000000000, "end": 1750003600000 }]
    }
  ],
  "cached": false
}
```

`GET /api/stations` returns `{line, directions, stations:[{id, name, lat, lon}]}` (`src/server.js:480`). `GET /api/lines` returns an array of `{id, name, color, directions, stationCount}` (`src/server.js:458`).

### 6.5 Client-side persistence

- Cookies (`public/app.js:103`): `bus_line`, `bus_direction`, `bus_station` — 10-year expiry, `path=/`, `SameSite=Lax`. `bus_station` is only written when location access has not been granted (`public/app.js:168`).
- `localStorage` (`public/capacitor-bridge.js:226`): `pushToken` — the device push token, written by the (currently unlinked) Capacitor bridge.
- Service worker Cache Storage (`public/sw.js:2`): a single cache named `st-tracker-v4` holding `/`, `/index.html`, `/style.css`, `/app.js`, `/manifest.json`, both SVG icons and `/sounds/orca-scan.mp3`. Old caches are deleted on activate (`public/sw.js:24`).
- `public/app.js` is loaded with a cache-busting query string `?v=20260120b` (`public/index.html:80`).

There is no server-side database, no ORM, and no schema or migration file anywhere in the repo.

### 8.2 Deployment

- **Container image** (`Dockerfile`): `node:20-alpine` base; a `nodejs` group/user is created with uid/gid 1001 before dependencies are installed; `npm ci --omit=dev`; `src/` and `public/` are copied with `--chown=nodejs:nodejs`; `EXPOSE 3000`; a `HEALTHCHECK` polls `http://localhost:3000/health` every 30 s; the process runs as the non-root `nodejs` user with `CMD ["node", "src/server.js"]`.
- **Compose** (`compose.yaml`): one service `bus-tracker` built from the Dockerfile, `container_name: bus-tracker`, `restart: unless-stopped`, port mapping `30089:3000`, `NODE_ENV=production`, `PORT=3000`, `env_file: .env`, and a `wget --spider` healthcheck on `/health` with a 30 s interval, 10 s timeout, 3 retries and a 10 s start period.
- **CI** (`.gitea/workflows/deploy.yml`): the real CI is Gitea Actions. On push to `main` it runs `appleboy/ssh-action@v1.0.0` against host `<deploy-host>` with `secrets.SSH_USER` / `secrets.SSH_PASSWORD`, then in `/srv/apps/bus` runs `docker compose down`, `docker compose build --no-cache` and `docker compose up -d`, finishing with `docker compose ps`.
- **Mobile packaging**: `npm run cap:sync` regenerates `www/` from `public/` and updates both native projects; `npm run android:build` produces a release APK under `android/app/build/outputs/apk/release/` (`MOBILE_BUILD.md:44`); `npm run ios:build` drives `xcodebuild` for the Release configuration. `www/`, `android/app/build/` and iOS build directories are git-ignored (`.gitignore:31`).

### 8.3 Testing

There is no JavaScript test suite. `package.json` defines no `test` script, there is no test runner in the dependency list, and no test files exist under `public/` or `src/`. The only tests in the repository are the two Android scaffolding files that Capacitor generates:

- `android/app/src/test/java/com/getcapacitor/myapp/ExampleUnitTest.java:14` — a JUnit4 local unit test asserting `4 == 2 + 2`.
- `android/app/src/androidTest/java/com/getcapacitor/myapp/ExampleInstrumentedTest.java:19` — a device instrumented test asserting the app context package name. Note its expected value is `"com.maxcapacitor.app"`-style literal `com.getcapacitor.app` (`android/app/src/androidTest/java/com/getcapacitor/myapp/ExampleInstrumentedTest.java:24`), which does not match the real `applicationId com.maxluo.sttracker` (`android/app/build.gradle:7`), so it would fail if run.

They are executed by Gradle (`./gradlew test` / `connectedAndroidTest`) and are not part of the Gitea Actions workflow, which only performs the SSH deploy. There is no CI job that builds the Docker image or runs any linter or test.
